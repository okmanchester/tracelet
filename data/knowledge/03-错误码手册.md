# 错误码手册

## 响应结构与错误码说明

所有接口返回统一 JSON 结构：

```json
{
  "code": "OK",
  "message": "success",
  "request_id": "req_20260615_8842",
  "data": {}
}
```

调用失败时 `code` 为对应的错误码，`message` 为可读说明。**`request_id` 是排查问题的唯一凭据**，联系技术支持或提交工单时请务必提供。

错误码按 HTTP 状态划分：401 鉴权、403 权限、400/402/404/408 请求、429 限流配额、500 服务端、200 业务结果。

## 错误码速查表

| 错误码 | 含义 | HTTP |
| --- | --- | --- |
| `AUTH_KEY_EXPIRED` | API Key 已过期 | 401 |
| `AUTH_KEY_INVALID` | API Key 无效 | 401 |
| `SIGN_INVALID` | 签名错误 | 401 |
| `PERMISSION_DENIED` | 权限不足 | 403 |
| `PRODUCT_NOT_ENABLED` | 接口未开通 | 403 |
| `IP_NOT_ALLOWED` | IP 不在白名单 | 403 |
| `NOT_FOUND` | 接口不存在 | 404 |
| `REQUEST_TIMEOUT` | 请求超时 | 408 |
| `RATE_LIMIT_EXCEEDED` | QPS 超限 | 429 |
| `QUOTA_EXCEEDED` | 调用量超额 | 429 |
| `INTERNAL_ERROR` | 服务端错误 | 500 |
| `PARAM_MISSING` | 参数缺失 | 400 |
| `PARAM_INVALID` | 参数格式错误 | 400 |
| `BALANCE_NOT_ENOUGH` | 余额不足 | 402 |
| `DATA_EMPTY` | 查询结果为空 | 200 |
| `DATA_INCONSISTENT` | 数据不一致 | 200 |
| `WEBHOOK_DELIVERY_FAILED` | 回调投递失败 | 200 |
| `WEBHOOK_SIGN_INVALID` | 回调验签失败 | 200 |

## AUTH_KEY_EXPIRED（HTTP 401）

**含义**：请求使用的 API Key 已超过有效期。

**常见原因**：Key 到期、新旧 Key 轮换后仍在使用旧 Key、环境配置过期。

**处理步骤**：

1. 登录控制台查看 Key 状态与过期时间。
2. 重新生成 API Key。
3. 更新服务端配置后重试。

## AUTH_KEY_INVALID（HTTP 401）

**含义**：API Key 不存在、被禁用或格式错误。

**常见原因**：Key 复制不完整、Key 已被禁用、误用了测试环境或其它应用的 Key。

**处理步骤**：

1. 核对 Key 是否复制完整，注意首尾空格与换行。
2. 确认 Key 未被禁用。
3. 使用控制台中的有效 Key 重试。

## SIGN_INVALID（HTTP 401）

**含义**：请求签名与服务端计算结果不一致。

**常见原因**：参数排序错误、拼接方式不一致、Secret 错误、时间戳偏差超过 5 分钟。

**处理步骤**：

1. 按文档对参数字典序排序拼接。
2. 确认使用正确的 Secret。
3. 校验时间戳在 5 分钟误差内。
4. 重新计算签名后重试。

详细规则见《鉴权与签名》。

## PERMISSION_DENIED（HTTP 403）

**含义**：当前应用无该接口或资源的访问权限。

**常见原因**：应用未开通对应产品、账号角色权限不足、访问了不属于本租户的资源。

**处理步骤**：

1. 确认应用已开通该 API 产品。
2. 联系管理员授权。
3. 重试。

## PRODUCT_NOT_ENABLED（HTTP 403）

**含义**：该 API 产品尚未为应用开通。

**常见原因**：新创建的应用未勾选目标产品，或产品刚开通尚未生效。

**处理步骤**：

1. 在控制台为应用开通对应 API 产品。
2. 等待生效后重试。

## IP_NOT_ALLOWED（HTTP 403）

**含义**：请求来源 IP 不在应用配置的白名单内。

**常见原因**：服务器出口 IP 变更、办公网访问、未配置白名单。

**处理步骤**：

1. 在控制台将服务器出口 IP 加入白名单。
2. 等待生效后重试。

## NOT_FOUND（HTTP 404）

**含义**：请求路径错误或接口已下线。

**常见原因**：路径拼写错误、版本号错误、接口已迁移或下线。

**处理步骤**：

1. 核对接口路径与版本。
2. 参考最新接口文档。

## REQUEST_TIMEOUT（HTTP 408）

**含义**：请求处理超时，可能为网络或上游处理较慢。

**常见原因**：上游数据源响应慢、客户端超时设置过短、网络抖动。

**处理步骤**：

1. 适当增大客户端超时时间。
2. 重试请求。
3. 持续出现请记录 `request_id` 并提交工单。

## RATE_LIMIT_EXCEEDED（HTTP 429）

**含义**：单位时间请求数超过套餐 QPS 限制。

**常见原因**：瞬时并发过高、批量任务未做限速、重试风暴。

**处理步骤**：

1. 客户端做本地限速。
2. 采用指数退避重试。
3. 错峰调用。
4. 如需更高并发请升级套餐。

详见《限流与重试》。

## QUOTA_EXCEEDED（HTTP 429）

**含义**：本月调用量已超出套餐配额。

**常见原因**：业务量增长、未及时升级套餐、异常调用耗尽配额。

**处理步骤**：

1. 查看本月用量。
2. 升级套餐或购买加量包。
3. 次月自动恢复配额。

详见《套餐计费规则》。

## INTERNAL_ERROR（HTTP 500）

**含义**：服务端内部异常。

**常见原因**：服务端偶发故障、依赖组件异常。

**处理步骤**：

1. 稍后重试。
2. 记录 `request_id`。
3. 持续出现请提交工单。

## PARAM_MISSING（HTTP 400）

**含义**：缺少必填参数。

**常见原因**：漏传必填字段、字段名为空、参数嵌套层级错误。

**处理步骤**：

1. 对照接口文档补齐必填参数。
2. 重试。

## PARAM_INVALID（HTTP 400）

**含义**：参数类型或格式不符合要求。

**常见原因**：证件号/手机号格式错误、枚举值非法、日期格式错误、参数类型不匹配。

**处理步骤**：

1. 核对参数类型与格式。
2. 修正后重试。

## BALANCE_NOT_ENOUGH（HTTP 402）

**含义**：账户余额不足以完成本次计费调用。

**常见原因**：余额耗尽、自动扣费失败、超额费用未结算。

**处理步骤**：

1. 在控制台充值。
2. 充值后重试。

## DATA_EMPTY（HTTP 200）

**含义**：请求成功但未命中数据。

**常见原因**：查询参数不匹配、数据未覆盖、产品范围不含该类数据。

**处理步骤**：

1. 核对查询参数。
2. 确认数据覆盖范围。
3. 如确认应有数据请提交数据质量工单。

详见《数据质量说明》。

## DATA_INCONSISTENT（HTTP 200）

**含义**：返回数据与预期来源存在差异。

**常见原因**：数据更新存在时间差、来源方数据调整。

**处理步骤**：

1. 查看返回的数据更新时间。
2. 提供对比样例并提交数据质量工单。

详见《数据质量说明》。

## WEBHOOK_DELIVERY_FAILED（HTTP 200）

**含义**：平台已发送回调，但客户地址返回非 2xx、超时或不可达。

**常见原因**：回调地址不可公网访问、处理超时未返回 200、防火墙拦截。

**处理步骤**：

1. 确认回调地址可公网访问。
2. 确保收到后 5 秒内返回 HTTP 200。
3. 平台会按重试策略自动重投。

详见《Webhook 回调》。

## WEBHOOK_SIGN_INVALID（HTTP 200）

**含义**：客户侧对回调验签失败。

**常见原因**：使用了错误的回调密钥、对原始 body 改写后验签、验签算法或编码不一致。

**处理步骤**：

1. 使用正确的回调密钥按文档验签。
2. 对原始请求体验签，不要反序列化后重新拼接。

详见《Webhook 回调》。
