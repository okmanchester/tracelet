## 背景与问题

会话列表按本人过滤，但详情、聊天复用和反馈仅检查租户；客户工单列表和查询工具也允许读取本租户其他用户的记录。不同入口表达了不同的资源边界。试用规划已明确客户管理员需要租户内查看能力，而续聊和反馈限本人；本提案将其转成统一、可验证的访问规则。

## 决策驱动因素

- 所有入口执行同一规则，不能通过模型工具、关联资源或更换接口绕过。
- 用户、角色和租户由服务端认证上下文确定；模型与客户端均不能指定代操作身份。
- 沿用现有用户、会话与工单字段，不引入委托、共享成员或新的权限基础设施。

## 替代方案与取舍

| 方案 | 如何解决问题 | 优点 | 成本、限制与风险 | 与驱动因素的关系 |
| --- | --- | --- | --- | --- |
| 保持租户级授权并逐入口修补 | 将列表放宽到整个租户 | 改动少 | 开发者可读取他人会话与工单；分散检查仍易遗漏 | 不符合已确认的访问目标 |
| 所有客户仅本人访问 | 所有入口同时限制租户与用户 | 规则简单，范围最小 | 客户管理员不能进行租户内查看 | 无法满足管理员需求 |
| 统一角色、资源与动作策略 | 查询条件和资源检查共同复用授权模块 | HTTP 与工具语义一致，可单独验证 | 需要维护动作差异和旧记录拒绝规则 | 已选，满足当前试用边界 |

## 已决定方案

已决定采用统一服务端策略，区分读取、客户写入和工作台操作：

| 身份 | 读取会话与工单 | 聊天、追加客户消息、反馈 | 工作台接管与人工回复 |
| --- | --- | --- | --- |
| customer_dev | 同租户本人记录 | 同租户本人会话 | 拒绝 |
| customer_admin | 同租户全部记录 | 同租户本人会话 | 拒绝 |
| support / admin | 跨租户查看 | 本人创建的会话；不能经客户入口写他人会话 | 允许处理客户会话 |
| 未知角色或缺失身份 | 拒绝 | 拒绝 | 拒绝 |

- 会话所有者取 `Conversation.user_id`。工单所有者取 `Ticket.user_id`；有关联会话时，其存在性、租户及所有者必须一致，才允许开发者读取。缺失、孤立或矛盾归属不向开发者放宽；管理员和内部人员仍可按上述读取范围核查。列表与详情采用相同规则。
- 新建工单的租户与创建人来自可信上下文；关联会话须按该动作授权并核对归属。模型传入不同的 tenant_id、user_id 或关联会话时拒绝，不据此代建。本批不自动改写旧记录。
- `ToolContext` 增加服务端用户 ID 和角色；Supervisor 的调用链传递完整身份。身份不完整时客户资源操作拒绝。保留现有内部标志的兼容调用时，也不能由该标志推导或提升角色。
- 统一策略提供资源读取/写入检查与列表过滤条件，覆盖会话、反馈、工单 HTTP 和工具入口；业务工具权限先检查，再执行查询结果返回或写入。其他租户级诊断工具不因此获得更广权限。
- 仅未指定 conversation_id 时新建会话；指定但不存在返回 404，存在但未授权返回 403，且不建会话、不写消息、不运行模型。
- 反馈类型限定为 resolved、unresolved、need_human；message_id 非空时须存在于目标会话，否则返回 422 且无业务写入。
- 成功请求主体和响应结构保持兼容。会话响应可增加 `can_write` 权限提示，由服务端计算，前端据此隐藏续聊与反馈；服务端仍独立执行检查。聊天 HTTP 失败必须正常展示并退出等待状态。
- 工单工具对不存在与无权限统一返回 found=false，不暴露他人内容。列表授权过滤在 limit 之前执行。

## 后果

### 正面后果

各入口具有可解释且一致的授权语义；管理员可以查看租户内记录；工具执行不再依赖模型声明的身份。以上保留提案形成时的目标；批准后的实施与验收记录见文末和关联问题。

### 负面后果与接受的取舍

开发者将失去此前可读的他人工单；无权限会话 ID 不再触发自动建会话。旧工单归属异常时，开发者可能暂时无法读取，需要人工核查。列表的关联归属核对会增加查询复杂度，未测量性能。

### 缓解措施与遗留问题

采用共享策略、数据库过滤测试和拒绝无副作用断言；不自动猜测旧记录所有者。幂等建单、人工状态迁移、会话并发分别留在 ARCH-003、002、005；本提案不承诺解决这些问题。

## 验证与重新评估条件

1. 至少两个租户、每租户两个开发者和一个客户管理员，以及 support/admin；验证每类角色的列表、详情、写入、反馈、工作台与工具查询。
2. 覆盖归属为空、工单与会话矛盾、无关联会话、跨租户及模型伪造身份；SQL 过滤与归属关系在隔离 MySQL 验证。
3. 验证拒绝前不执行模型、不创建消息/反馈/工单；无权限、未知会话及非法反馈返回约定结果。
4. 管理员查看他人会话时按钮隐藏，直接发送请求仍被拒绝；HTTP 非成功响应不会留在等待状态。
5. 完整隔离回归零失败、零错误、零跳过，保存报告并清理资源。

需要租户内代操作、共享会话、支持人员分配范围或新的角色模型时重新评估，不以扩大现有布尔判断隐式实现。
