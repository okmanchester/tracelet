### ARCH-009 运行时间约定

- 运行路径使用带时区的真实 UTC；现有 MySQL 无时区 DATETIME 按模型已有 UTC 写入约定解释，本批不迁移列或改写旧数据。带时区输入按同一时刻转换为 UTC。
- Key 在 `expire_at <= now` 时过期；工具和反馈工单的日期段均取创建时 UTC 日期。旧工单 ID 不重写。
- “近 N 分钟”默认截至当前 UTC，默认 60 分钟；查询窗口为 `(start, end]`，返回明确窗口起止和 realtime/historical 模式，不包含上界之后的数据。
- 历史诊断仅在显式指定本租户调用 request_id 时以事件时间为上界；事件无权限、不存在或与接口不符时不回退为另一窗口。此 request_id 是业务调用日志标识，与四份 Proposed 中新增的聊天操作 UUID 不同。
- 诊断查到具体调用后传递该事件作为统计锚点；无有效事件则查询实时窗口。零调用也是有效证据，不因为 total=0 而被丢弃。
- 种子脚本的固定样本日期保留；日常服务不提供冻结时钟配置，旧样本的“当前过期”结果随真实时间变化。确定性复现通过测试/离线进程替换 clock.now_utc，不改变正常服务默认值。

### 部署与操作约定

本批只在随机测试库执行迁移，不自动修改现有开发或试用库。部署时先停止旧 worker 和写入、备份目标独立数据，按现有入口执行 `python -m scripts.migrate_db upgrade` 和 `check`，再协调发布必填 UUID 的前后端版本、重启全部 worker。未接管的旧库仍须先按 ADR-0001 核查并显式接管，不自动标记版本；DDL 部分失败按现有规范核查后前向修复。

任务 worker 随应用生命周期启动；`EFFECT_WORKER_ENABLED=false` 可停用后台消费但任务仍持久化。管理命令在 backend 目录执行：`python -m scripts.effect_tasks list --operation op_<操作ID>`、`python -m scripts.effect_tasks retry <任务ID>`、`python -m scripts.effect_tasks drain --limit 100`。重试仅接受最终失败任务，列表不输出任务载荷。图执行无节点检查点，崩溃恢复可能重复只读诊断及模型调用，不能保证模型费用恰好一次；操作历史和缓存任务去重标记当前不自动清理。

### 请求与追踪标识

| 使用位置 | 标识语义 | 生成方及用途 |
| --- | --- | --- |
| POST /api/chat、/api/feedback；GET /api/operations/{kind}/{request_id} | request_id 为客户端操作 UUID | 客户端生成一次，按认证租户、用户和操作类型限定；查询及重试保持不变，与诊断目标 API 调用无关 |
| 操作查询结果、附属任务管理命令 | operation_id 为服务端操作关联标识 | 查询结果输出 op_ 加身份范围摘要；数据库与可信 ToolContext 内部传递原摘要，任务命令接受 op_ 前缀；不能拿客户端 UUID 代替 |
| 日志查询工具参数、collected_entities、Ticket.related_request_ids；GET /api/traces?request_id= | request_id 为待诊断的客户 API 调用标识 | 来自业务调用日志，如 req_…；traces 参数经工具参数摘要反查涉及该调用的 trace，不查询聊天操作 |
| trace_id | 一次编排的链路标识 | 服务端生成；重试重新执行模型时可产生新 trace，同一操作的最终结果仍按操作标识查询 |

保留已接受的 UUID 接口，不在普通复核中实施破坏性字段改名。文档和讨论分别称“客户端操作 UUID”和“API 调用 ID”，不得混用。
